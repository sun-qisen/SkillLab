## 1. 背景与范围

todo-manager skill（`todo-manager/`，含 `scripts/todo.py` CLI + SKILL.md）投入实际使用后
发现四类问题，本迭代逐一修复：

1. 缺少行程安排建议能力，尤其是可并行任务分析；
2. `list` 默认视图会带出已完成任务；
3. 凌晨 0:00–4:00 说"明天/后天"等相对日期时，应按前一天的语境换算；
4. 循环任务 bug：下一期 `next_due` 从完成日 `date.today()` 推算，导致提前完成时
   下一期截止日过近（如周六完成周日截止的周任务，下一期变成明天到期）。

**明确不做（本迭代）**：可视化界面（L2 参考服务）。其架构已定稿于
`E:\MyProject\sunmoo\docs\superpowers\specs\2026-07-11-todo-backend-architecture-design.md`，
另起对话单独走 spec → plan → 实现。

## 2. todo.py 改动

### 2.1 逻辑日（4 点日界线）

- 新增 `logical_today()`：当前本地时间减 4 小时后取日期，即凌晨 0:00–3:59 归前一天，
  4:00 起算新一天。日界线以常量 `DAY_CUTOFF_HOUR = 4` 硬编码（个人工具，不进 config，YAGNI）。
- 全脚本替换 `date.today()` 调用点，统一走逻辑日：
  - `pick_view` 的 today / week 筛选（含 week_end 计算）；
  - `is_overdue` 过期判断；
  - `fmt_due` 相对日期渲染（"今天 / 明天 / 过期 N 天"）；
  - `cmd_list` 头部日期、`cmd_report` 的周起点与"本周完成"上界；
  - 循环任务推算基准（见 2.3）。
- **数据时间戳不变**：`created_at` / `updated_at` / `completed_at` / journal `ts`
  仍记录真实时间；逻辑日只影响"哪一天"的语义判断。
- 可测性：环境变量 `TODO_MANAGER_NOW`（ISO 8601 时间，仅测试/调试用）可冻结
  "当前时间"，`logical_today()` 与相关渲染均从该时刻推导。

### 2.2 list 默认排除已完成

- `--view all` 语义改为**全部活跃任务**：排除 `done` / `cancelled`。
  `today` / `week` / `blocked` 本就只含活跃任务，不受影响。
- 新增 `--include-done` 开关：与 `--view all` 连用时返回含已完成/已取消的全量列表；
  对 `today` / `week` / `blocked` 视图无效果（这三个视图语义上就是活跃任务视图）。
- 特例：`--view all` 下显式传 `--status done` 或 `--status cancelled` 时自动包含
  已完成项（否则该过滤器永远为空，自相矛盾）；其它视图不受此特例影响。

### 2.3 循环任务 next_due 修复

- `finalize_done` 生成下一期时，推算基准从"完成日"改为**任务原 due**；
  无 due 的循环任务保持从完成日（逻辑日）推算。
- 若推算结果不晚于完成日（拖延补做场景），按规则**逐期推进**直到严格晚于完成日
  （逻辑日）。效果：
  - 节奏锚定原周期：`every:3:days` 保持 1/4/7/10 的节拍，`weekly:sun` 永远落在周日；
  - 提前完成不再压缩周期：周六完成周日截止的 weekly:sun，下一期为下周日；
  - 拖延补做不会生成即过期的任务。

## 3. SKILL.md 改动

### 3.1 行程安排建议（新增小节，置于"查询"工作流之后）

**触发**：仅当用户发出排程类请求（"今天怎么安排 / 先做哪个 / 帮我排一下"）时进入；
普通"今天要做什么"只列清单，不强行给建议。

**方法**：

- 输入依据：`list --view today` 结果 + 优先级、截止日期、预估耗时（estimate_minutes）。
- 并行分析三原则：
  1. 真并行 = 一个任务存在**固有等待间隙**（浸泡、下载、等回复、机器自行运行）时，
     把另一个任务穿插进间隙——如"泡鞋的 20 分钟里清理扫地机器人"；
  2. 需要连续专注操作的任务是串行的，不建议同时进行；
  3. 互相独立 ≠ 可并行——没有真实穿插机会就不硬凑，直接给串行顺序。
- 输出形式：建议顺序 + 穿插点（若有）+ 一句话理由，不长篇大论。

### 3.2 凌晨日界线推断规则

日期推断规则中新增：凌晨 0:00–4:00 期间用户说的"今天 / 明天 / 后天 / 周 X"按
**前一天的语境**换算（如 7/12 凌晨 1 点说"明天" = 7/12 而非 7/13），并注明 CLI 的
今天/过期判断同样按 4 点日界线，两边口径一致。

### 3.3 视图说明同步

`list` 视图表更新：`all` = 全部活跃任务；查看已完成需 `--include-done`
（或 `--status done`）。

## 4. schema.md 改动

无数据结构变化。仅在行为说明处补一句逻辑日口径（4 点日界线），供未来 UI 对接时
与 CLI 判断一致。

## 5. 测试计划

沿用现有模式（pytest + subprocess 跑真实 CLI + `--data-dir` 临时目录）：

- **逻辑日**：注入 `TODO_MANAGER_NOW` 为凌晨 2 点，验证 today 视图、过期判断、
  "今天/明天"渲染均按前一天算；4:00 整点边界归新一天。
- **list 默认**：默认与 `--view all` 均不含 done/cancelled；`--include-done` 包含；
  `--status done` 自动包含。
- **循环修复**：提前完成（周六完成周日截止的 weekly:sun → 下一期下周日）；
  拖延补做（逐期推进到未来且保持节拍，覆盖 every:N:days）；无 due 循环任务
  回退完成日推算；monthly 月末边界不回归。
- **测试基建**：测试 `run()` 统一注入固定 `TODO_MANAGER_NOW`（当天中午），
  消除套件对运行时刻的隐性依赖；现有断言（如依赖 `--view all` 含已完成项的）随之微调。

SKILL.md 提示词部分（排程建议、凌晨换算）属 Agent 行为，不进单元测试；
如需评估，后续可用 skill-creator 的 eval 流程补充。

## 6. 错误处理

- `TODO_MANAGER_NOW` 格式非法时忽略并回退真实时间（仅测试通道，不为此报错）。
- 其余错误路径（校验、锁、损坏兜底）不变。

## 7. 验收标准

1. 凌晨 2 点（模拟）查 today 视图，看到的是前一天视角；"明天"渲染指向当前自然日。
2. `list` 默认输出不再出现已完成任务；`--include-done` / `--status done` 可见。
3. weekly:sun 任务周六完成后，下一期截止日为下周日（而非明天）。
4. 全部测试（含新增）在 Windows 原生 Python 下通过。
